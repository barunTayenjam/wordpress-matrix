<objective>
Eliminate credential exposure in process listings, harden .env file permissions, and prevent accidental credential commits.

**Purpose**: MySQL passwords currently pass via `-p"$PASSWORD"` CLI arguments, visible to any user running `ps aux`. `.env` files are created without restrictive permissions. There's no guard against committing credentials.

**Output**: 5 shell files with all password-carrying call sites converted to `MYSQL_PWD` env var, `.env` creation hardened with `chmod 600`, and a pre-commit hook blocking credential commits.
</objective>

<interfaces>
<!-- Key patterns used across all shell files -->

From bash conventions:
- `$CONTAINER_RUNTIME` is either `docker` or `podman`
- `$DOCKER_COMPOSE` is either `docker-compose` or `podman-compose`
- All DB containers are accessed via `wp_db` container name
- Two password variables: `MYSQL_ROOT_PASSWORD` (root) and `MYSQL_PASSWORD` (wp_user)
- Fallback pattern: `${VAR:-default}`

Replacement pattern:
```
# BEFORE: $CONTAINER_RUNTIME exec wp_db mysql -u root -p"${MYSQL_ROOT_PASSWORD:-root}" -e "..."
# AFTER:  $CONTAINER_RUNTIME exec -e MYSQL_PWD="${MYSQL_ROOT_PASSWORD:-root}" wp_db mysql -u root -e "..."
```

For DOCKER_COMPOSE exec calls:
```
# BEFORE: $DOCKER_COMPOSE exec -T db mysql -u root -p"${MYSQL_ROOT_PASSWORD:-root}" ...
# AFTER:  $DOCKER_COMPOSE exec -T -e MYSQL_PWD="${MYSQL_ROOT_PASSWORD:-root}" db mysql -u root ...
```

    #!/bin/bash
    # Pre-commit hook: reject commits containing MYSQL_PASSWORD strings
    # This prevents accidental credential leakage into git history.
    
    set -euo pipefail
    
    # Check staged files for MYSQL_PASSWORD (case-sensitive)
    if git diff --cached --diff-filter=ACM --name-only -z | xargs -0 grep -l 'MYSQL_PASSWORD' 2>/dev/null; then

        echo "This looks like a credential string that should NOT be committed."
        echo "If intentional, use --no-verify to bypass this check."
        exit 1
    fi

## Trust Boundaries

| CLI ↔ Process Table | Credentials cross from script variable space into OS-level process listing |
| .env file ↔ Filesystem | Credentials stored on disk with permissions determined by umask |
| Git history ↔ Developer workstations | Committed credentials become permanently accessible in repository history |

| T-05-02 | Information Disclosure | .env file creation in setup_env() and repair_env() | mitigate | Add `chmod 600 "$PROJECT_ROOT/.env"` after every `cat > .env` write to prevent world-readable credentials |
